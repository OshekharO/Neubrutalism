## 2026-03-06 - [CSS Transition and Animation Layer Optimizations]
**Learning:** `transition: all` across reusable CSS framework components causes browsers to calculate layout and paint property transitions for all properties during hover/state changes, leading to unnecessary main-thread style recalculations and layout thrashing. Explicit property declarations (`transition: transform, box-shadow, color...`) constrain transition evaluation to target properties. Continuous keyframe animations (`.nb-spinner`, `.nb-skeleton`, `.nb-pulse`) benefit from `will-change` layer promotion for 60 FPS GPU compositor rendering.
**Action:** When working on CSS frameworks, audit `transition: all` usage and replace with specific properties being animated, and promote continuous animated elements using `will-change`.
